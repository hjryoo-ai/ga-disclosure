# Phase 5 계획 승인 (2026-10-03)

## 판정: 승인. Q1~Q14 중 Q2·Q13은 대안, 나머지 권장안. 보강 4건

단서: 이번에 받은 것은 **계획의 표지와 질문 요약**이고 `docs/phase-05-계획.md`(`8bbf030`) 본문은 보지 못했다. 질문 14건은 요약만으로 결정할 수 있어 여기서 결정한다. 항목 ①~⑦(DDL·머클 규격·TSA·보고서 스키마·파기 산식·계약 결과·모듈 위치)은 수용 심사 때 계획 커밋과 보고서를 대조한다. 계획 갱신 1커밋 후 착수, 재승인 불요.

## 1. 인정하는 것

- **SeaweedFS 스파이크를 커밋하지 않고 돌린 것**, 그리고 거기서 "버전 ID 없는 삭제는 없는 키에도 삭제 마커를 남긴다"를 잡아 **파기는 버전 ID로만 삭제**로 바꾼 것. 계약 테스트 항목이 하나 더 생겼다(없는 키 삭제 후 마커 0).
- **OSV 조회의 대조군**(1.77은 9건)으로 "0건"이 조회 실패가 아님을 증명한 것. 부재 증명은 이렇게 해야 한다.
- **잠금 만료가 데모에서 자연히 일어날 수 없다**는 것을 계획 단계에서 찾아 두 가지 조건으로 분해한 것(Q6). 착수 후 발견했으면 데모 설계를 되돌려야 했다.
- Q3. 작은 정의역의 해시는 값 자체라는 지적. 지시문의 "지운 값의 해시"를 그대로 따랐으면 생년월일·전화번호를 지운 척 남기는 셈이었다.

## 2. 결정

## 3. 보강

- **B1. 계약 테스트 추가 항목**: 버전 ID 없는 삭제를 어댑터가 **절대 보내지 않음**(요청 캡처), 없는 키의 버전별 삭제 뒤 마커 0, 보류 중 객체는 보존 만료 뒤에도 삭제 거부(스파이크 결과를 테스트로 옮긴다).
- **B2. G14 주입 목록에 추가**: `SET LOCAL ROLE` 없이 앱 롤로 파기 함수 호출 → 거부 확인. 함수 표식 없이 파기자 롤의 직접 UPDATE → 거부 확인. 데모 시계 오프셋 키를 운영 프로파일에 넣기 → 기동 실패 확인.
- **B3. Q6(b) 경로의 감사**: `RETENTION_ALREADY_ELAPSED`가 운영 프로파일의 봉인 경로에서 **한 번도 나오지 않는다**는 것을 Phase 0~4 전체 IT의 감사 스캔으로 확인(평문 스캔과 같은 방식).
- **B4. 설계서 v1.11**: Q1(모듈 배치 §3.3), Q2(파기 트랜잭션 §9), Q3(남기는 것 열), Q7·Q5(부록 D), Q9·Q10(§9 보존 산식과 룰 적용 시점), Q13(검증 보고서 문장 §6).
