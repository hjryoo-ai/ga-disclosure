# Phase 4 계획 승인 (2026-10-02)

## 판정: 승인. Q1~Q13 중 Q13만 대안 채택, 나머지 권장안. 보강 3건

계획 §10 순서로 진행. 계획 갱신 1커밋 후 착수, 재승인 불요.

## 1. 인정하는 것

- **서명본 증분 갱신을 계획 단계에서 실험**해 두 실패(`/ID` 둘째 값의 시각 의존, 저장 전 가져오기 시 폰트 미임베드)를 원인까지 찾아 둔 것. 3B의 "세 지점 고정"이 서명본에도 네 번째 지점으로 확장된 셈이다. 실험 코드는 커밋하지 않았으니 본 구현의 골든 테스트가 같은 두 조건을 다시 증명해야 한다(G7).
- 3B 일탈 9건 중 D1만 따로 올린 판단. "불변식을 넓히지 않았다"를 스스로 판정하고 경계 사례 하나를 심사에 넘긴 것이 맞다.

## 2. 결정

| # | 결정 | 덧붙임 |
|---|---|---|
| Q1 | **D1 유지.** 고정 룰 로드는 `apply_from ≤ 상담일`만 확인 | 소급 배포로 밀려난 초안이 **읽히지도 않는** 상태가 더 나쁘다(재기준조차 못 함). 봉인 조건 ①②가 막으므로 봉인 규약은 그대로. 조건 하나 추가: 로더는 `status ∈ {ACTIVE, RETIRED}`만 받고(`DRAFT`·`APPROVED` 거부), 로드한 body 해시가 3A 검증 감사에 기록된 고정 시점 해시와 같아야 한다(불변이지만 검사는 싸다). Q12 폐기. |

## 3. 보강

- **B1. G14 주입 목록에 추가**: 서명본을 증분 갱신이 아니라 재생성으로 만드는 주입 → 접두 테스트 실패 확인. `/ID` 시드를 시각 기반으로 되돌리는 주입 → 골든 실패 확인.
- **B2. 토큰 접두 테넌트의 존재 누설 금지**는 Phase 6 공개 엔드포인트 완료 기준으로 이월하되, 유스케이스 층에서 "없는 테넌트"와 "틀린 토큰"이 **같은 예외 타입**을 내도록 지금 맞춘다.
- **B3. 설계서 v1.9**에 Q1~Q13 결정을 각 절에 반영(§3.3·§4.5·§5·§6.5·부록 D). D1은 §6.4 1항의 B1 예외 문단에 "로더는 시작일만 본다, 봉인이 막는다"로.
