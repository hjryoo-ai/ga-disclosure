# Phase 5 수용 심사 결과 (2026-10-03)

## 판정: 수용. PR #8 병합 승인(merge commit), `phase-5` 태그 유지

병합 게이트가 지켜졌다. 단, 아래 §2의 **반영 지시 3건**은 Phase 6A 첫 커밋에서 한다(병합을 막지 않는다 — 셋 다 의미를 좁히는 쪽이고 데이터 변경이 없다).

## 1. 인정하는 것

- **"없는 키를 버전 없이 삭제해도 마커가 생긴다"를 커밋하지 않은 스파이크에서 잡고, 어댑터를 나열 기반 ID 삭제로만 만든 뒤 SDK 인터셉터로 "버전 없는 DeleteObject를 보내지 않는다"를 요청 캡처로 단언한 것.** 파기의 "흔적 0"은 이 사실을 몰랐으면 거짓이 될 뻔했다.
- **CI 실패를 세션 시간대로 추적하고, `TZ=UTC`로 재현한 뒤 고치고, 전체 check를 `TZ=UTC`로 한 번 더 돌린 것.** 하나를 고치고 "다른 시간대 의존이 없다"까지 증명했다.
- **V7′ 첫 주입 실패 0**을 "객체 존재만 확인"의 빠진 테스트로 읽고 산출물 해시 변조 테스트를 더한 것. S9(Phase 4)와 같은 태도다.
- **보고서 (c)의 `ANCHORS` PASS 설명.** 앵커는 재계산 머리와 대조하므로 저장 해시 변조에 PASS가 맞고, 단절은 `SEAL_CHAIN`이 한 번만 보고한다는 해석이 정확하다. 이것을 결함으로 오해하지 않은 것이 중요하다.
- **P-2.** 계획의 주입 "함수가 감사 seq 대조 생략"이 Q2 대안에서 성립하지 않음을 알아보고, 같은 보장(거부된 파기의 감사는 남지 않는다)을 깨는 다른 주입으로 바꾼 것. 주입은 테스트가 아니라 보장을 겨눈다.
- 사용자 compose 볼륨을 지우지 않은 것. `down -v`는 사용자의 결정이다.
- `pii-columns` 표에 **RETAINED 행과 "PII가 아니라고 판단한 것"을 명시**한 것. 지우지 않기로 한 것도 결정이므로 표에 있어야 한다.

## 2. 반영 지시 (Phase 6A 첫 커밋)

**R1. 앵커 소급 기입 폐지.** 데모가 쓴 "지금 머리를 어제 날짜로 기록"은 `anchor_date`의 의미를 흐린다 — 날짜 라벨은 2일인데 머리는 3일 것이다. 검증 문장이 `created_at`을 쓰므로 거짓은 아니지만, 라벨을 시각으로 읽는 사람이 반드시 나온다. 빠진 날은 다음 앵커가 어차피 덮으므로(증명 구간이 길어질 뿐 공백이 아니다) 소급은 증거 가치가 없다. 조치: `anchor` 테이블에 `CHECK (anchor_date = (created_at AT TIME ZONE 'Asia/Seoul')::date)`(V12), `anchor run --date`는 시계의 KST 날짜와 다르면 거부(`DATE_NOT_TODAY`), `DATE_NOT_AFTER_LATEST`는 자연히 사라진다. 빠진 날은 `verify tenant` 운영 발견 `ANCHOR_MISSING_DAY`(CHAIN_BROKEN 아님). 데모의 "두 날"은 데모 전용 시계 오프셋(이미 있음)으로 만든다. 설계서 §6.7 문장 수정.

**R2. 데모 번들 표류 방지.** `DISC-DEMO-SHORT`가 규제 번들과 별개의 GLOBAL 전체 룰이므로 둘이 벌어질 수 있다. 테스트 추가: 데모 번들 = 규제 번들 − {보존 키들}(차집합이 보존 키만인지 단언). 규제 번들이 바뀌면 데모 번들도 같은 커밋에서 바뀌도록.

**R3. `VERIFY_RUN` 감사 행 확인.** 지시문 §4가 요구한 `verify tenant`의 감사 1행(보고서 해시)이 보고서 어디에도 보이지 않는다. 있으면 PR #8 코멘트로 테스트 이름을, 없으면 6A 첫 커밋에서 추가하고 `TombstoneIT.aReappearingObjectAndAnUnauditedDestructionAreFound`와 같은 방식으로 "감사 없는 검증 실행"을 발견으로 잡는다.

## 3. D1~D19 판정

전부 수용. 넓힌 불변식은 없다. 짚어 둘 것:

- **D8** `CHAIN_BROKEN`은 무결성 발견만 — 맞다. 운영 신호(`ANCHOR_UNSTAMPED`·`TSA_UNTRUSTED`·R1의 `ANCHOR_MISSING_DAY`)는 Phase 6B 준법 큐의 별도 유형이다.
- **D9** 함수가 기파기에 GD114로 거부 — 계획보다 엄격하므로 수용. 배치가 단계 전에 상태를 읽는 것이 멱등의 근거라는 점을 설계서에 한 줄.
- **D12** 보류 해제 사유 어휘 — §14 #15로 두지 않고 **6A에서 룰 키 `legalHoldReleaseReasons`(닫힌 목록)로 닫는다.** 설정 사유와 같은 패턴이라 미결정으로 남길 이유가 없다.
- **D16** DEMO3가 규제 번들을 받지 않는 것 — 두 GLOBAL이 겹치면 Ambiguous라는 판단이 맞다. R2가 그 대가다.
- **D18** B3 스캔 범위가 infra IT — 봉인 경로가 거기 있으므로 수용.

## 4. Phase 6 질문 9건에 대한 결정

Phase 6은 **둘로 나눈다.** 6A = 인가·REST·고객 공개 서명·이벤트 피드·작업 엔드포인트·통지 아웃박스(기반). 6B = 준법 큐·징구율·계약 연결·청약 게이트·초안 폐기·보존 재계산(업무). 엔진 E4 지시문은 6B와 함께 낸다 — 6B의 계약 연결·게이트가 엔진에 무엇을 요구하는지 정해진 뒤가 맞다.

| # | 결정 |
|---|---|
| 1 인가 | **채택.** 토큰은 주체만, 나머지는 `identity_link`. `AuthorizationPort.require(actor, action, target)`를 유스케이스 진입점에. 범위 AGENT=자기 `agent_id`, MANAGER=`org_path` 접두, COMPLIANCE=테넌트 전체(열람 전부 감사). **보류 설정·해제는 COMPLIANCE, 해제는 4-eyes**(`released_by <> placed_by`를 유스케이스와 DB CHECK 양쪽에). **`verify tenant`는 COMPLIANCE가 실행 가능**(읽기 + 감사 1행뿐이므로), 테넌트당 동시 1건(advisory lock). **파기 배치는 사람 역할에 노출하지 않는다** — 시스템 스케줄러만; `--dry-run` 결과 열람만 COMPLIANCE. 교차 테넌트 접근은 403이 아니라 **존재 누설 없는 404**로 통일. |
| 2 REST | **채택.** OpenAPI 정본 확장, `Idempotency-Key`(테넌트·키별 응답 해시 저장, TTL 룰 데이터), 오류 `{code, message, details}`(메시지에 개인정보 0), 상태 충돌 409·검증 거부 422, 커서 페이지, 긴 작업은 202 + 작업 리소스. 스키마 형식은 D14의 교훈대로 `pattern`. **검증 보고서·영수증 내보내기는 REST로 노출하되 COMPLIANCE 전용·열람 감사.** 내보내기는 바이트 그대로(워터마크 없음 — 해시가 깨진다); Q14 워터마크는 Phase 7 화면 미리보기에만. |
| 3 공개 서명 | **채택 + 보강.** 공개 인그레스는 별도 보안 필터 체인(경로 접두 `/public/`), 토큰은 헤더·본문으로만 — 고객 링크는 **URL 프래그먼트**(`#` 뒤, 서버·액세스 로그에 가지 않음)에 토큰을 싣고 Phase 7 화면이 본문으로 보낸다는 규약을 지금 문서화. 거부 응답은 모든 사유(없는 테넌트·틀린 토큰·만료·취소·사용됨)에서 **같은 상태·본문·헤더**, 응답 시간은 **고정 하한으로 패딩**(통계 테스트가 아니라 패딩 적용을 훅으로 단언). 테넌트·토큰 해시 단위 한도는 앱(룰 N회), IP 단위는 인그레스(Phase 8 문서). 응답에 PDF 외 개인정보 0. **통지 사업자는 §14(운영 결정)**, 지금은 `notification_outbox`(재시도·백오프 룰 데이터, 소진 시 `NOTIFY_FAILED` 플래그)와 콘솔 어댑터. |
| 4 준법 큐 | **6B.** `CHAIN_BROKEN` 해소는 클릭이 아니라 "원인 조치 후 `verify tenant` MATCH"로만 — 채택. SLA 수치는 **룰 데이터**(테넌트 오버라이드 가능)로 두되 기본값을 지어내지 않는다(기본 null = SLA 없음, 테넌트가 정한다). |
