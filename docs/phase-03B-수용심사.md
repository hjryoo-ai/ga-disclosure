## 1. 인정하는 것

- **골든 PDF 3건이 Linux CI와 macOS 로컬에서 바이트 동일.** 3A 계획 승인 때 "실패하면 WeasyPrint로 전환"이라는 조건을 걸었는데, 동봉 폰트·ICC와 세 지점 고정만으로 통과했다. 결정론을 매 빌드가 검사한다.
- **SeaweedFS 볼륨 한도 CI 실패의 처리.** 디스크 여유 공간으로 볼륨 한도를 정하는 동작을 원인까지 추적하고, 로컬에서 한도를 줄여 **같은 오류를 재현한 뒤** 하네스·compose 양쪽에 고정하고 회귀 테스트를 붙였다. "CI 러너가 작아서"로 끝내지 않은 것이 맞다.
- **`HASH_MISMATCH` 열람 거부 경로의 누락 테스트**를 찾아 추가하고, 해시 비교를 끈 상태에서 실패함을 확인한 것. 거부 경로는 성공 경로보다 테스트가 빠지기 쉽다.
- **3A 로컬 DB 위에 3B를 돌리면 서식 재배포가 거부되는 것**을 결함이 아니라 불변 규칙의 정상 동작으로 읽고 README에 `down -v`를 적은 것. 같은 ID·다른 해시의 거부는 Phase 1 C5가 정한 그대로다.

## 2. 결정

1. **CLAUDE.md 문구 수정 승인.** "Testcontainers(PostgreSQL·SeaweedFS — S3 호환 + Object Lock, digest 고정)"로. 규칙 파일이라 멈춘 판단은 옳았다. 앞으로 규칙 파일의 **사실 오류 정정**(도구 이름·버전 같은)은 보고서에 적고 바로 고쳐도 된다. 규칙의 **의미 변경**만 승인 대상이다.
2. **정정 사유 원문 보존: V8에 추가 승인, 단 무효 사유와 같은 형태로 통일한다.** 둘 다 `reason_code`(룰 데이터 `voidReasons`·`supersedeReasons`의 닫힌 목록) + `reason_text`(선택, 길이 상한은 룰 데이터) 두 컬럼. 원문은 원본 확인서 행의 메타 컬럼(`superseded_by_id`와 함께 write-once)에 둔다. 사유 텍스트에 고객 정보를 적지 않도록 하는 것은 Phase 7 화면 안내 문구와 Phase 6 준법 큐의 몫이며, 코드로 막지 않는다(막을 수 없다).

## 3. Phase 4 질문 6건에 대한 결정 (7번째는 계획에서 올릴 것)

| # | 질문 | 결정 |
|---|---|---|
| 1 | 서명을 PDF 해시에도 묶을지 | **둘 다 묶는다.** `signed_doc_hash = canonical_hash`(설계 불변식)에 더해 `signed_pdf_hash = pdf_hash`(V8). 서명자가 본 것은 PDF 바이트이므로 증거는 PDF에, 문서 정체성은 canonical에 귀속된다. 트리거가 둘 다 부모 컬럼과 대조. |
| 2 | 서명본 PDF 생성 방식 | **원본 PDF에 증분 갱신(incremental update)으로 서명 외관 페이지를 덧붙인다.** 원본 바이트가 서명본의 **접두(prefix)** 로 남아 `pdf_hash`를 서명본에서도 검증할 수 있다(테스트: 접두 동일). 서명본도 결정론(입력 = 원본 + 서명 레코드, 시각은 레코드의 `signed_at`)이고 PDF/A-2b를 유지해야 한다(veraPDF 잡에 서명본 추가). 암호학적 PAdES 서명은 아니다 — 증거력은 우리 체인·증거 패키지에 있다는 것을 설계서에 명시. |
| 3 | 완료 시 보존기한 연장 | 룰 데이터 `retentionAnchors: ["SEAL", "COMPLETION", "CONTRACT_DATE"]`. `retention_until = max(각 앵커 날짜 + retentionYears)`를 앵커가 생길 때마다 재계산해 **연장만** 한다(3B Q6 트리거 그대로). 계약 연결(policy-link)은 Phase 6에서 같은 함수를 호출. |
| 4 | 서명 스트로크·이미지·스캔의 암호화 키 | **문서 DEK 재사용**, AAD = `tenant_id`·`disclosure_id`·`signature_id`·`kind`. 문서 키를 파기하면 서명 증거도 함께 읽을 수 없어야 한다(생체 유사 정보가 문서보다 오래 남으면 안 된다). |
| 5 | 서명 진행 중 무효·정정 | 상태표대로 허용. 이미 기록된 서명은 append-only로 남고(무효·정정된 문서에 귀속된 채), **열린 서명 세션은 전부 `REVOKED`**·원격 링크 즉시 무효. 정정으로 생긴 새 버전에 서명은 이월되지 않는다(§6.6). 고객 통지는 Phase 6 `NotifyPort`. |
| 6 | 식별부 라벨 확정 일정 | 외부 사실(§14 #2). 지금은 일반 한국어 라벨을 서식 데이터에 두고 `TODO(confirm#2)` 표시는 데이터에만(렌더에 나오지 않음). 확정 시점은 **Phase 7(프론트) 착수 전**으로 하고, 사용자가 협회 표준서식 원문을 확보할지 그때 결정한다. 봉인·서명을 막지 않는다. |
