# Phase 7 지시문 — 화면 (v1.1 — 서식 확보 건너뜀)

## 역할과 맥락

`ga-disclosure` Phase 6B(`phase-6B`, PR #10) 수용 후. 대상은 설계서 **§7(API 표면), §8(화면 — 있으면), §6.4(서식 데이터·렌더), §9(공개 서명 링크 규약·미리보기 워터마크), §12 Phase 7, §14 #2(식별부 라벨)·#4·#22**와 Phase 6A·6B 수용심사의 Phase 7 이월 항목(Q14 워터마크, 플래그 가시성 룰, 모르는 필드 400). 사용자 결정(2026-10-09): **협회 표준확인서 서식 원문은 확보하지 못했으므로 건너뛴다.** 식별부 라벨은 지금의 일반 한국어 라벨과 `TODO(confirm#2)`(데이터에만, 렌더 안 됨)를 유지하고 §14 #2는 미결정으로 남는다. 라벨이 서식 데이터이므로 원문이 확보되면 **새 서식 버전**으로 바꿀 수 있고(기존 봉인 문서는 고정 버전 유지), 그때 코드 변경은 0이어야 한다 — 이번 Phase가 그 전제를 지킨다. 배포·인그레스·매니페스트는 Phase 8.

이 Phase가 끝나면 다음이 테스트로 증명돼야 한다.

1. 확인서의 식별부 라벨·항목 순서·필수 표기가 **서식 데이터**(출처 기록 포함)에서 오고, 코드에 라벨 문자열이 없다. 기존 봉인 문서는 **고정된 서식 버전**으로 그대로 렌더된다.
2. 화면은 서버 계약(OpenAPI)에서 **생성한 클라이언트**만 쓰고, 화면에 업무 판단이 없다 — 거부는 서버 코드를 보여 줄 뿐이다.
3. 고객 서명 화면은 토큰을 **URL 프래그먼트에서 꺼내 본문으로** 보내고, 토큰·개인정보가 브라우저 저장소·로그·분석 도구·URL 어디에도 남지 않는다.
4. 화면 미리보기 PDF에만 워터마크가 있고, 내보내기·증거 패키지는 바이트 그대로다.

## 0단계 — 서식 교체 가능성 증명 (작게, 1단계 선행)

서식 원문이 없으므로 전사는 하지 않는다. 대신 **"원문이 오면 코드 변경 0으로 새 서식 버전만 배포하면 된다"** 를 지금 증명한다.
- 테스트용 가상 서식 버전(`forms/test-alt-labels.json`, 라벨만 다른 변형, 커밋은 테스트 리소스로)을 새 버전으로 배포해 ① 기존 봉인 문서는 고정된 이전 버전으로 렌더되고 골든 PDF 3건 + 서명본 골든이 **그대로 통과**, ② 새 문서는 새 라벨로 렌더, ③ 두 버전 공존 — 를 `TemplateVersionsIT`로. 제자리 수정은 Phase 1 C5가 거부함을 재확인.
- 코드에 한국어 라벨 문자열이 0건임을 스캔(화면 코드 포함 — 화면 라벨도 서식 데이터 또는 `Problem.code` 사전에서만 온다).
- `TODO(confirm#2)`는 데이터에 그대로, §14 #2 미결정 유지. 서식 확보 시 할 일(전사·대응표·공백 목록·출처 기록, 원문 미커밋)을 §14 #2에 **절차로** 적어 둔다.

## 시작 전 보고

계획에 ① 6B 보고서 D 표 전체 + T4·P4 표 ② 0단계 결과 ③ 프런트엔드 스택 제안(아래 제약 안에서 — 프레임워크·빌드·테스트 도구, 각각 안정판 버전과 라이선스) ④ 화면 목록(역할별)과 각 화면이 부르는 계약 경로 ⑤ 공개 서명 화면의 분리 전략(별도 번들·인증 라이브러리 0) ⑥ 미리보기 워터마크 서버 엔드포인트 설계 ⑦ E2E 테스트 전략(데모 프로파일 위에서) ⑧ Phase 7 질문을 넣고 승인 후 진행.

**스택 제약**: TypeScript strict(`any` 0), OpenAPI 계약에서 **생성한** 클라이언트만(수기 fetch 금지, 계약 drift 시 빌드 실패), 런타임 CDN·서드파티 스크립트·분석 도구 0, 폰트는 번들(PDF와 같은 폰트), 락 파일·라이선스 목록, 모든 의존성 안정판·OSV 확인. 프레임워크 선택은 계획에서 제안하되 "왜 이것인지"를 한 문단으로 — 장식적 비교표는 필요 없다.

## 작업 목록

### 1. 모듈·빌드 (`disclosure-web`)
- Gradle 하위 프로젝트로 Node 빌드를 감싼다(CI 한 번에). 산출물은 데모 프로파일에서 앱이 같은 출처로 서빙(`/`·`/s`), 운영 분리는 Phase 8.
- 계약 클라이언트 생성 태스크: `contracts/api/v1/*.openapi.yaml` → 클라이언트. 생성물은 커밋하지 않고 빌드마다 만든다. 계약 변경 없이 클라이언트 코드가 바뀌면 실패(결정론).
- CSP 엄격(`default-src 'self'`, 인라인 스크립트 0), `Referrer-Policy: no-referrer`, 공개 서명 페이지는 `Cache-Control: no-store`.

### 2. 역할별 화면 (`/api/v1` 소비, 데모 OIDC 로그인)
- **AGENT**: 고객 등록(응답은 가명뿐 — 화면도 이름을 다시 보여 주지 않는다; 입력값은 제출 후 메모리에서 지운다), 초안 작성(항목·비교·등급 요청·추천사유 입력 — **시스템은 추천사유를 쓰지 않는다**, 자동완성·예시 문구 0), 검증 결과(플래그 중 `visibleToAgent`만), 봉인, 서명 세션 발급(TOUCH_PAD는 현장 서명 화면으로 이어짐, REMOTE_LINK는 "발송 대기"만), 설계사 서명, 자기 확인서 목록·상세·PDF 미리보기.
- **MANAGER**: 조직 범위 목록, 확인서 상세 + **플래그 목록·확인(acknowledge)**, 관리자 확인(서명 또는 승인 클릭 — 룰 `agentSignMethod` 계열 그대로), 종이 스캔 검토, 예외 승인, 무효, 징구율(조직).
- **COMPLIANCE**: 준법 큐(유형·SLA·담당·해소 — `CHAIN_BROKEN`은 해소 버튼이 아니라 "검증 실행 → MATCH 확인 → 해소" 흐름), 보류 설정·해제(4-eyes 안내), 검증 작업 제출·보고서 열람, 영수증 내보내기, 파기 dry-run 보고서 열람, 보존 재계산(dry-run 기본), 징구율(전체·"내부 지표 — 규제 정의 없음" 표기 그대로).
- 모든 화면: 서버 `Problem.code`를 사람 문구로 바꾸는 **단일 사전**(코드 → 문구), 사전에 없는 코드는 코드 그대로 표시(숨기지 않는다). 거부 사유 문구에 고객 정보 0.

### 3. 고객 공개 서명 화면 (`/s#{token}`, 별도 번들)
- 프래그먼트에서 토큰을 읽어 메모리에만 두고 `history.replaceState`로 URL에서 제거, `X-Sign-Token` 헤더로 `status → open → view → verify-identity → capture`. 저장소(`localStorage`·`sessionStorage`·쿠키·IndexedDB) 사용 0.
- PDF 열람: 스크롤 완료·열람 초를 측정해 `view`로 보고(룰 `SCROLL_COMPLETE`). 본인확인 입력(생년월일 등)은 제출 후 즉시 메모리에서 지우고 어떤 로그에도 남기지 않는다.
- 터치 서명: 포인터 이벤트로 스트로크(좌표·시각 시퀀스, Phase 4 JSON 형식)와 렌더 PNG를 만들어 `capture`. 기기 정보는 Phase 4 `device` 형식만.
- 거부(서버 404 동일 응답)는 사유를 구분하지 않는 **한 화면**("이 링크는 사용할 수 없습니다")으로 — 화면이 사유를 추측하지 않는다.
- 인증 라이브러리·라우터·상태 관리 라이브러리 0(작게).

### 4. 미리보기 워터마크 (서버, 작은 추가)
- `GET /api/v1/disclosures/{id}/preview.pdf`(ARTIFACT_VIEW 인가·감사 사유 `PREVIEW`): 봉인 PDF 위에 "열람용 · {역할} · {시각 KST}" 워터마크를 **실시간 생성, 저장 안 함**. PDF/A 요구 없음. 기존 산출물 엔드포인트는 바이트 그대로(테스트: 해시 동일). 공개 서명 화면의 PDF는 **워터마크 없음**(고객이 서명하는 원본이어야 한다).

### 5. 테스트
- 단위(컴포넌트)·계약(생성 클라이언트가 계약 예시와 일치)·**E2E**(Playwright, 데모 프로파일 + 격리 컨테이너): 역할별 핵심 흐름 1개씩, 공개 서명 전체 흐름, 거부 화면 1개, 접근성 검사(axe — WCAG 2.1 AA 기준 위반 0, 예외는 사유와 함께 목록).
- **누출 스캔(브라우저 측)**: E2E 실행 후 브라우저 저장소·콘솔 로그·네트워크 로그(URL·헤더)·스크린샷 파일명에 토큰·이름·전화·생년월일(동적 센티널) 0건. 서버 측 스캔은 6A·6B 그대로 돈다.
- 시각 회귀는 두지 않는다(결정론 비용 대비 가치 낮음) — 대신 핵심 화면의 **DOM 스냅샷**(라벨이 서식 데이터와 같음).

### 6. 데모
- `seed.sh`·`http-demo.sh` 유지 + `e2e-demo`(Playwright 헤드리스)가 같은 흐름을 화면으로 1회 수행하고 스크린샷을 `build/demo/phase7/`(gitignore)에 남긴다. README에 로그인 계정(데모 OIDC)·역할별 둘러보기 순서.
