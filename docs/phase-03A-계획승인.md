## 2. 계획에 대한 보강

**B1. 룰·서식 버전을 초안 생성 시 고정하는 것의 예외 경로.** 고정은 옳다(기준일 = 상담일이므로 봉인 시 재해석과 결과가 같다). 단 하나의 예외가 있다 — **소급 적용되는 룰 배포**(apply_from ≤ 상담일인 새 GLOBAL·TENANT 버전이 초안 생성 후 배포됨). 이 경우 고정 ID와 재해석 결과가 달라진다. 3A에서는 `RuleResolver.load`가 고정 ID로 로드만 하되, **3B의 SEAL 조건에 "상담일 재해석 결과 = 고정 ID"를 넣고 다르면 봉인 거부 + `compliance_flag(RULE_SUPERSEDED_DRAFT)`**를 둔다. 재기준(rebase) 명령은 3B에서 정의(COMPARED로 회귀 + 새 ID 고정). 설계서 §6.4 1항에 이 예외를 함께 적는다.

**B2. 감사 실패 기록 규약 — 승인.** 업무 거부는 커밋·감사, 예외는 롤백 후 별도 트랜잭션 `COMMAND_FAILED`(메시지 없음)라는 분류를 설계서 §6.2에 표로 넣는다. 한 가지 추가: `COMMAND_FAILED`의 별도 트랜잭션도 **같은 테넌트 컨텍스트** 안이어야 하며(RLS), 컨텍스트가 없어서 실패한 명령은 감사 대상이 아니라 401/기동 오류다. W7에 "테넌트 미바인딩 명령은 `COMMAND_FAILED`를 남기지 않는다" 1건 추가.

**B3. W1의 문서 파싱.** 설계서 §6.1의 상태 × 명령 표는 테스트가 파싱하는 **정본**이 되므로, 마크다운 표가 아니라 fenced 블록(`state-table` 언어 태그, CSV)으로 둔다. 표 형식을 사람이 고치다 파서가 깨지는 일을 막기 위해서다. 미구현 명령(SEAL 이후)은 표에 있되 테스트는 "구현 여부"를 별도 목록으로 갖고, 3B가 구현할 때 그 목록만 줄인다.

**B4. 엔진 자격 증명.** `HttpEngineTransport`의 서비스 토큰은 3A에서 **`EngineCredentialPort`**(테넌트별 환경 설정에서 읽는 구현)로 받는다. `tenant.params`(평문 JSONB)에는 넣지 않는다. Phase 8 운영 조립에서 Phase 2 볼트 기반 구현으로 교체(엔진 심사 §4-4).

## 3. 3B 선결정: PDF 변환기는 openhtmltopdf

실측 결과로 지금 정한다. **openhtmltopdf 1.1.x**(JVM 내 실행, PDF/A-2b 준수, 세 지점 고정 시 바이트 일치). WeasyPrint는 기본값으로 결정론·준수를 만족하지만 Python·Pango 사이드카와 프로세스 경계가 생기고, 봉인 p95 3초·장애 격리 목표에서 비용이 더 크다. 3B 조건:
- 문서 정보 날짜·XMP 날짜·`/ID` 시드 **셋 다 봉인 입력(canonical 해시·확인서 번호)에서 파생**. 벽시계 참조 0.
- sRGB ICC 프로파일·폰트(NanumGothic OFL, 라이선스 파일 포함)를 **저장소에 동봉**하고 빌드 시 내려받지 않는다. `verification/pdf-candidates/`도 동봉 폰트를 쓰도록 바꾼다.
- 3B 완료 기준에 **CI(Linux)와 로컬(macOS arm64)의 PDF SHA-256 일치**를 넣는다. 이 조건이 ICC·폰트 고정 후에도 실패하면 WeasyPrint 사이드카로 전환하고 그 사실을 설계서 결정 기록에 남긴다.
- Boot BOM 적용 시 의존성 겹침은 `checkBom`으로 3B 첫 커밋에서 확인.
