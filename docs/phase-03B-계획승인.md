# Phase 3B 계획 승인 (2026-10-01)

## 판정: 승인. Q1~Q12 전부 권장안 채택, 보강 4건

계획 §10 순서로 진행한다. 계획 문서 갱신 1커밋 후 착수, 재승인 불요.

## 1. Q1 — 오브젝트 스토리지: SeaweedFS 4.48 채택 (지시문의 MinIO 대체)

MinIO 이미지가 Docker Hub에서 사라진 것은 공개 보도로 확인했고(2026-09-11~14), quay.io는 9월 25일 시점 기사에서는 살아 있다고 했으나 9월 30일 직접 조회에서 manifest가 없었다는 실측을 우선한다. 어느 쪽이든 마지막 커뮤니티 릴리스(RELEASE.2025-09-07)가 동결돼 이후 CVE가 영구히 열려 있다는 점만으로도 **준법 증거 저장소의 개발·CI 기준 구현으로 부적합**하다. 지시문의 "MinIO"는 내 오류이며 설계서 §11·§3.2의 "개발: MinIO"도 함께 고친다.

- SeaweedFS(Apache-2.0, 장기 유지)를 개발·CI 기준으로 쓴다. RustFS는 1.0 정식이 9월 16일이라 이력이 짧고, Garage는 Object Lock을 제공하지 않는 것으로 알고 있어 후보에서 뺀다(확인이 다르면 보고).
- **어댑터는 벤더 무관 S3 API만 쓴다**(AWS SDK v2, Q12). SeaweedFS 전용 API·헤더 사용 금지. 운영에서는 Object Lock을 지원하는 어떤 S3 호환 저장소든 어댑터 교체 없이 붙어야 한다.
- 이미지는 **digest로 고정**(태그 아님). 이번 일이 "태그가 사라질 수 있다"의 실례다.
- **S9에 Object Lock 계약 테스트를 추가**한다. 9월 30일 boto3로 실측한 5가지(잠긴 버전 삭제 거부, 우회 헤더 삭제 거부, 기한 단축 거부, 기한 연장 허용, 잠기지 않은 객체 삭제 허용)를 어댑터·컨테이너에 대해 도는 통합 테스트로 옮긴다. 이 테스트가 저장소 교체 시의 수용 기준이다.

## 3. 보강

- **B1. 지시문 §5·S9 정정**: "MinIO" → "SeaweedFS(digest 고정)", S9에 Object Lock 계약 테스트 5종 추가. 설계서 §3.2·§11 동일.
- **B2. 저장소 교체 가능성 증명**: S9 계약 테스트를 `ArtifactStoreContract`(추상)로 두어 다른 S3 호환 구현을 붙일 때 같은 테스트를 상속하게 한다(Phase 1 `DisclosurePolicyRepositoryContract`와 같은 패턴).
- **B3. 헤더 항목의 `bind`**: `HEADER_DISCLOSURE_NO`·`HEADER_CONSULT_DATE`·`HEADER_AGENT`·`HEADER_CUSTOMER_NAME`. 성명은 봉인 유스케이스만 채운다(렌더러는 canonical의 값을 읽을 뿐 복호화 경로 없음).
- **B4. 엔진 승인 2건은 E4 첫 커밋에서** — 확인. 엔진 저장소는 그때까지 손대지 않는다.
