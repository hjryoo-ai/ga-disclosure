# Phase 7 계획 승인 (2026-10-10)

## 판정: 승인. 0단계 수용. 넓힘 2건(Q1·Q3) 승인, Q4 승인, 스택 승인(조건 2). 보지 못한 질문은 권장안

단서: 받은 요약은 Q4 중간에서 끊겼고, "화면 구현을 좌우하는 여섯" 중 셋(번호 미상)과 나머지 여덟은 보지 못했다. 그것들은 **권장안 채택**이되, 인가 표·계약·불변식을 넓히는 것이 있으면 보고서에 표시한다(이미 Q1·Q3을 표시했으므로 나머지는 넓히지 않는 것으로 읽는다). 계획 갱신 1커밋 후 1단계 착수, 재승인 불요.

## 1. 0단계 — 수용

- 가상 새 서식 버전을 **실제 배포 경로**로 배포해 ① 기존 문서 바이트 불변(저장본·재렌더 모두) ② 골든 4건 불변 ③ 새 문서는 새 라벨·상담일 기준 공존 ④ 제자리 수정 거부 — 네 가지를 한 IT로 증명했다. 서식 확보 시 코드 변경 0이라는 전제가 섰다.
- **서식 쪽 제자리 수정 거부에 Phase 1 C5 테스트가 없었다**는 발견을 기록한다. 규칙은 있었고 테스트가 없었다 — 이번에 처음 생긴 것이 맞고, Phase 1 심사의 누락이다.
- `LabelLiteralScanTest`의 "한글 리터럴은 사유를 단 닫힌 목록 18개 파일에만" — 수용. 목록은 폐기 항목 검사 포함(다른 허용 목록과 같은 규약).
- 지시문과 다른 점 셋(`rule-as-data/templates/` 위치, `deviceFingerprint` 문자열, 토큰 헤더 단일화) 전부 수용 — 셋 다 계약·저장소 규약이 지시문 문언보다 옳다.

## 2. 결정

| # | 결정 | 조건 |
|---|---|---|
| Q1 (넓힘) | **`FLAG_READ` AGENT OWN 칸 승인** | 필터는 **서버 유스케이스**에서(`visible_to_agent` 행만 — 화면 필터 금지). 테스트: 룰 변형으로 한 유형을 `visibleToAgent=true`로 바꾸면 그 유형만 보이고 나머지 0, 룰 기본(전부 false)에서는 빈 목록이되 **404가 아니라 200 빈 배열**(칸이 있다). 다른 설계사의 확인서는 404. |
| Q3 (넓힘) | **`GET /api/v1/disclosures/{id}/template` 승인** | 읽기 전용, 범위 = `DISCLOSURE_READ`와 동일(OWN/ORG/TENANT). 응답은 그 확인서가 **고정한 서식 버전의 라벨 집합**과 버전 ID·번들 해시만(업무 판단 0). 초안(고정 전)은 상담일 기준 ACTIVE 서식을 주고 응답에 `pinned:false`로 표시. `ETag` = 번들 해시. 감사는 `DISCLOSURE_VIEW`에 포함(별도 행 없음). |
| Q4 | **`messages.ko.json` 하나로 승인** | 화면 문구 + `Problem.code` 문구. 조건: **서식 라벨은 여기 두지 않는다**(Q3에서 온다) — 테스트: 메시지 파일의 값 집합과 서식 라벨 집합의 교집합 0. 사전에 없는 코드는 코드 그대로 표시(지시문 G3). 한글 리터럴 스캔을 `disclosure-web`까지 넓혀 이 파일 외 0건. |
| 스택 | **승인** — React 19 + Vite + TS strict / 고객 서명은 무프레임워크 + pdf.js 번들 / openapi-typescript + 생성물 해시 잠금 / Playwright + axe | 조건 ① pdf.js는 **워커까지 번들**(CDN 0)하고 `isEvalSupported: false`로 CSP에서 `unsafe-eval` 없이 동작함을 E2E가 CSP 위반 0으로 단언. 라이선스(Apache-2.0) 목록에. ② 스크롤 완료의 정의를 계획에 한 줄로 고정: "마지막 페이지가 렌더되어 뷰포트에 들어온 시점"이고 열람 초는 단조 시계(`performance.now`)로 — 둘 다 `view`로 보고. 버전·라이선스는 계획 ③의 안정판 기준 그대로(OSV 확인 보고서에). |
