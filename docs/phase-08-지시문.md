# Phase 8 지시문 — 배포·운영·정비·포트폴리오 문서 (v1.0)

## 역할과 맥락

`ga-disclosure` Phase 7(`phase-7`, PR #12) 수용 후. 마지막 Phase다. 대상은 설계서 **§3.2(실행 환경), §9(키·보존·허용 목록 — `DatabaseHealthIndicator` 예외), §11(CI·검증), §12 Phase 8, §14 전체(미결정 정리)** 와 Phase 5~7에서 Phase 8로 이월된 항목(스케줄러 매니페스트, 인그레스 노출 단위·IP 한도, 운영 분리, 성능 인덱스, 폰트 번들 상한, E2E 스냅샷 마스킹, 룰 어휘 읽기 경로, 환급금 표 렌더, 6B 이월분). 새 업무 기능은 없다. 이 Phase의 산출물은 **운영 가능한 배포 묶음 + 복구 증명 + 포트폴리오로 읽히는 문서**다.

이 Phase가 끝나면 다음이 증명돼야 한다.

1. 빈 환경에서 **문서만 보고** 배포 → 데모 → `verify tenant` MATCH까지 간다(사람이 재현).
2. **백업에서 복구한 환경**에서 모든 테넌트의 `verify tenant`가 MATCH이고 영수증·TSA 검증이 통과한다. 복구는 증거 체계의 일부다.
3. 모든 비밀(KEK·커서·영수증·요청 해시·TSA 신뢰 앵커)은 이미지·저장소·로그에 없고 비밀 저장소에서만 온다. 키 회전 절차가 각 키마다 문서화되고 한 번씩 실행됐다.
4. `/internal`은 클러스터 밖에 열리지 않고, `/public`은 별도 호스트·IP 한도 아래 있으며, 사람 역할의 `/api`와 분리된다.

## 시작 전 보고

계획에 ① Phase 7 보고서 §5 전체 + 넓힘·계약 추가 표 ② 6B 이월분 **목록**(Phase 7 질문의 "6B 이월분"은 항목이 적혀 있지 않았다 — 적어라) ③ 배포 형태 제안(권장: Kubernetes 매니페스트 + Kustomize, 로컬은 kind; 대안이면 이유) ④ 비밀 주입 방식(권장: 외부 비밀 저장소의 CSI/ESO 연동 — 실제 벤더 연동은 인터페이스·문서까지, 로컬은 kind 시크릿) ⑤ 백업·복구 절차와 복구 증명 테스트 설계 ⑥ 환급금 표 수정 방법(아래 §3 제약 안에서) ⑦ 포트폴리오 문서 목차를 넣고 승인 후 진행.

## 작업 목록

### 1. 배포 묶음 (`deploy/`)
- 이미지: 앱(JVM)·화면(정적, 별도 서빙)·마이그레이션 잡 — 베이스 이미지 **digest 고정**(3B SeaweedFS 규약), 비루트, 읽기 전용 루트 FS, 이미지에 비밀·키 파일 0(테스트: 이미지 레이어 스캔).
- 마이그레이션: `disclosure_migrator` 롤로 도는 **선행 Job**(앱은 마이그레이션을 돌리지 않는다 — 기동 시 버전 불일치면 실패). `init-roles.sql`의 롤 5종(앱·마이그레이터·파기자·폐기자·작업 잠금)과 정의자 롤을 매니페스트로.
- 스케줄: CronJob 매니페스트 — 앵커(플랫폼 CLI `anchor run --tenants all`), 만료·재적용·파기·통지·멱등 정리·플래그 SLA·징구율 스냅샷·유휴 초안 폐기(각 테넌트 작업은 작업 엔드포인트 또는 CLI, 6A 잠금 그대로). 시간대 KST 명시, 겹침 금지(`concurrencyPolicy: Forbid`) + 앱의 advisory lock이 2중 방어임을 문서에.
- 인그레스: `/api`(사람, 사내 IdP), `/internal`(클러스터 내부만 — NetworkPolicy + 인그레스 미노출, 게이트는 mTLS 종단), `/public`(별도 호스트, IP 단위 분당 한도·요청 크기 한도·TLS만). 테스트: 매니페스트 린트 + kind에서 `/internal` 외부 접근 거부·`/public` 한도 동작.
- 설정: 운영 프로파일 필수 키 목록(패딩 하한·링크 base URL·TSA URL·신뢰 앵커·IdP issuer·키 파일 경로)이 없으면 **기동 실패**(테스트: 키 하나씩 빼고 기동 → 실패 메시지가 키 이름만).
- 헬스: `DatabaseHealthIndicator` — 직접 접근 허용 목록 **다섯째 항목**(설계서 §9에 예정돼 있던 것). 테넌트 데이터를 읽지 않고(`SELECT 1` + 마이그레이션 버전 조회) 전용 롤 불요(앱 롤, 테넌트 바인딩 없음)인 이유를 적고 ArchUnit에 FQN 등재. 준비성(readiness)은 DB·저장소·IdP JWKS, 활성(liveness)은 프로세스만.
- 관측: 메트릭(작업 성공·실패·소요, 공개 경로 거부 수, 미고정 앵커 일수, 큐 SLA 초과 수) — 라벨에 테넌트 ID는 허용, 그 밖의 식별자·개인정보 0(테스트: 라벨 키 닫힌 목록). 로그는 JSON 구조화, 누출 스캔을 **배포 전 검사**로(데모 환경 로그 전체에 센티널 0).

### 2. 비밀·키 회전·백업·복구
- 비밀: KEK(테넌트별)·커서 키·영수증 키·요청 해시 키·데모 OIDC 키·TSA 신뢰 앵커 — 비밀 저장소 인터페이스(`SecretSource` 포트, 파일·환경변수·외부 저장소 어댑터)로 통일. 저장소·이미지·로그에 0건(스캔).
- **키 회전 런북** 키마다: 영향(커서 키 → 진행 중 커서 무효, 영수증 키 → 만료 뒤 NOOP 영수증 변경, 요청 해시 키 → 진행 중 청구 재생 불가, KEK → 재래핑 작업 필요: `document_key`·고객 키 재래핑 배치 `KEK_REWRAP` 신설, 감사·dry-run·연장 전용 아님에 주의), 절차, 검증 명령. **각 키를 한 번씩 실제로 회전**하고 그 뒤 `verify tenant` MATCH·E2E 통과를 보고서에.
- 백업: PostgreSQL 논리/물리 백업 + 저장소 객체 버전 포함 복제 — 보존기간은 룰 보존기간 이상, 백업 암호화, Object Lock 백업본도 잠금.
- **복구 증명(G2)**: 데모 환경을 백업 → 빈 환경에 복구 → 모든 테넌트 `verify tenant` MATCH·영수증 `verify package` 0·앵커 TSA 토큰 검증 통과·`artifacts reconcile` 0건 — 자동화된 테스트(CI는 선택, 로컬 재현 필수).

### 3. 정비 (이월분)
- **룰 어휘 읽기 API** `GET /api/v1/rules/vocabulary`(인증된 사람 역할 전부): 테넌트의 오늘 ACTIVE 룰에서 **닫힌 목록만**(무효·정정·보류 설정·해제·폐기 사유, 플래그 유형·해소 코드, 채널·역할 어휘) — 값·임계치·파라미터는 주지 않는다. 화면의 자유 입력을 선택 입력으로 바꾸고, 서버 거부는 그대로(화면 판단 0). 계약 추가형.
- **환급금 표 렌더**: 먼저 원인이 서식(HTML/CSS 데이터)인지 렌더러 코드인지 가른다. 서식이면 **새 서식 버전**(데이터 변경, 코드 0 — Phase 7 0단계가 증명한 경로). 렌더러 코드면 **렌더러 버전을 문서에 고정**(매니페스트·`document_artifact`에 `rendererVersion`)하고 기존 문서는 옛 렌더러로 재렌더되게 한다 — 그렇지 않으면 Phase 7 `TemplateVersionsIT`의 "재렌더 바이트 동일"이 거짓이 된다. 골든은 새 버전만 추가, 기존 골든 불변. 어느 쪽인지 계획 ⑥에서.
- 성능: 감사 로그·확인서 목록·플래그 큐의 인덱스를 **실측**(데모 데이터 ×N 생성 스크립트로 10만 행 수준) 뒤 추가. "느릴 것 같아서"는 근거가 아니다 — 플래너 사용 테스트(6B V20 방식).
- 폰트 번들 상한: 화면·PDF 폰트 크기 측정 → 서브셋 가능 여부(PDF 폰트는 **결정론 때문에 바꾸지 않는다** — 바꾸면 골든이 깨진다; 화면 폰트만). 상한은 측정값으로 정하고 빌드가 초과 시 실패.
- E2E 실패 스냅샷: Playwright 설정에서 입력값 마스킹(센티널이 스냅샷에 0 — 실패를 일부러 내서 확인), CI 아티팩트 제외는 유지.
- 6B 이월분 목록대로 — 계획 ②.

### 4. 포트폴리오 문서 (`README.md`·`docs/`)
- 독자는 **처음 보는 엔지니어**다. `README.md`: 한 문단 요약(무엇을, 왜 — 규제 배경 2줄, 출처 링크), 아키텍처 그림 1장(모듈·경계·외부 의존), 15분 둘러보기(kind 배포 → 데모 → 화면 → `verify tenant`), 설계서·Phase 문서 색인.
- `docs/ARCHITECTURE.md`: 대전제 7개가 코드 어디서 어떻게 강제되는지(규칙 → 테스트/트리거/ArchUnit 매핑 표). `docs/EVIDENCE.md`: 증거 체계(봉인·체인·앵커·TSA·영수증·검증)를 **한 문서의 수명주기**로 따라가며 설명, 실제 데모 산출물(해시 앞 12자리)로.
- `docs/DECISIONS.md`: Phase별 수용심사·계획승인에서 나온 결정 중 **되돌리거나 틀렸던 것**을 포함해 시간순으로(지시문 오류·심사 누락 포함 — 포트폴리오의 가치는 거기에도 있다).
- 숫자는 전부 CI 보고서에서(테스트 수·주입 수·E2E 수). 형용사 금지("강력한"·"완벽한"), 미결정(§14)과 알려진 한계(패딩 상수의 규모 상한 추정, 규제 징구율 정의 없음, 협회 서식 미확보, 실 TSA·통지 사업자 미연동)를 **첫 화면에**.
- 스크린샷은 Phase 7 E2E 산출물에서(허구 데이터, 개인정보 센티널 스캔 통과본만).
